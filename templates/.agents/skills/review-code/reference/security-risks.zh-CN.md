# 安全风险检视

## 适用范围

当变更触及认证授权、非可信输入、敏感数据、凭据、加密、依赖或系统边界时使用。

## 检视问题

- 信任边界、权限检查和默认拒绝行为是否保持清晰。
- 输入验证、输出编码、秘密处理和日志记录是否避免扩大暴露面。
- 新依赖或系统调用是否引入未被方案覆盖的能力或供应链风险。

## 证据要求

沿入口、校验、授权、数据使用和失败出口记录调用链或数据流；用测试、规范冲突或准确位置支撑结论。

## 常见反例

- 仅因使用了安全相关 API 就判定安全。
- 只检查正常路径，不检查绕过路径和失败默认值。
- 把无法访问真实凭据或外部系统直接归为 blocker。

## 无法闭环时

可复现缺陷形成 finding；必须在真实权限或外部系统中执行的检查进入 manual-validation；证据不足的未覆盖边界记录为 gap，不得无条件通过。
