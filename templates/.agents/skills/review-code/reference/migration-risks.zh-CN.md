# 迁移与兼容风险检视

## 适用范围

当变更触及持久化格式、schema、配置/frontmatter、兼容读取、迁移或回滚行为时使用。

## 检视问题

- 兼容是否通过 `.agents/rules/compatibility-policy.md` 的对象、必要性、期限和退出条件准入；未准入时是否应直接 current-only。
- 获准转换是否集中在一个边界，转换后只写当前格式，而不是让业务核心理解多个版本。
- 若确需迁移，是否可重复执行，部分失败后能否恢复或安全停止。
- 删除旧格式时，专属分支、fixture、测试和文档是否同轮删除。

## 证据要求

先记录兼容准入证据；获准兼容时再记录旧输入到当前状态的唯一转换、版本判定、退出条件和失败状态。优先使用消费者/存量数据证据、迁移测试、fixture、状态转换或规范冲突。

## 常见反例

- 没有真实消费者或存量数据，只因“可能需要”就保留旧读取。
- 同时写新旧格式，或在主路径里维护多套状态机。
- 假设迁移一次成功，忽略重试和部分写入。
- 用格式存在性测试替代数据语义验证。

## 无法闭环时

未经授权的兼容层、双写或无退出条件 shim 形成 finding。已获准迁移中的可复现数据损坏形成 finding；需要真实历史数据的验证进入 manual-validation；缺少兼容准入证据时不能仅记录 gap 后放行。
