# 通用规则 - 生命周期技能禁言

> 仅适用于「生命周期类」技能：`analyze-task` / `plan-task` / `implement-task` / `review-task` / `refine-task`（如发生重命名，对照重构任务的迁移表更新引用方）。
> 非生命周期技能（如 `create-task`、`commit`、`complete-task`、`import-issue`）的本职就包含与用户确认，不受本规则约束。

## 禁言条款

生命周期技能在**执行过程中禁止向用户提问**。

具体约束：

1. **禁止调用** 任何向用户发问的工具（包含但不限于 `AskUserQuestion` 及等价的「征求用户选择」机制）。
2. **不确定时**，按「最稳健方案」自主推进，不中断对话。最稳健方案的判定优先级：
   1. 与现有代码 / 文档 / 规则一致的方案优先
   2. 可逆性更高的方案优先
   3. 影响面更小的方案优先
3. **如存在假设或未决问题**，写入产物中的固定段落，不在对话中悬置：
   - `## Assumptions`：本次按某假设推进，未来若该假设不成立可推翻
   - `## Open Questions`：本次未决、需要人工审查时裁定的问题

   产物模板未预留这两段时，按需追加；没有假设或未决问题时不必强行写空段。
4. 仅在**真正不可逆的破坏性操作**（如即将 `git push --force`、`rm -rf` 用户工作树）前可短暂确认；常规方案选择不属于此类。

## 人工审查检查点语义

「强制性人工审查检查点」（mandatory human review checkpoint）的语义是：

- **产出后停止**：技能完成产物（如 `plan.md`）后立即结束本轮调用，等待用户主动触发下一个技能命令
- **不是过程中暂停征求意见**：不允许在执行步骤之间插入「请问您倾向 A 还是 B？」之类的中断

如果在执行过程中发现需要用户裁定的关键决策，按上文「假设与未决问题」处理，记录到产物的 *Open Questions* 段落，由用户在审查检查点统一回应。

## 引用方式

各生命周期 SKILL.md 在「行为边界 / 关键规则」段落以单行引用本规则：

> 禁言规则：执行过程中遵守 `.agents/rules/no-mid-flow-questions.md`；先读取该规则文件。
