# 校验输出摘要规则

本规则约束 `task-verify --format text` 及生命周期技能向用户展示校验结果的方式。它不改变校验逻辑、结构化结果或持久化证据要求。

## 总体摘要

- 展示总体状态、校验目标，以及通过、失败和阻塞计数。
- 成功结果只展示摘要，不列出通过项名称。
- 失败与阻塞保持不同状态；只列出有效失败或阻塞项的稳定标识、简明原因和可执行动作。
- raw 状态失败但 effective 状态通过的软检查，不得计入失败；需要提醒用户时用简短警告及必要原因和动作说明。
- raw 状态阻塞但 effective 状态通过的软检查，也必须显示简短警告，并保留 raw 阻塞状态、必要原因和动作说明。
- 通过结果若包含已消费的人工作出豁免或其他必须保留的例外证据，应显示简短提示并保留例外证据；该检查仍按 effective 状态计数。

## 消费边界

- 不把完整成功 stdout 复制到最终回复。需要检查通过项明细时，按需读取结构化结果或重新运行命令。
- 宿主 finalization 等结构化结果按其状态、receipt 和 warning projection 消费；不要将 receipt 原文当作用户摘要。
- 持久化生命周期报告继续遵循 `evidence-reporting.md`，记录可复现范围、状态和必要证据；Issue artifact 评论继续同步所需报告内容。
- JSON payload、检查顺序、检查集合、effective status 判定和退出码均不受本规则影响。
