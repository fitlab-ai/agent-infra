# 人工裁决上下文契约

本规则约束 analyze、plan、code 及三类 review 工作流中新建的所有 `[needs-human-decision]` 详情块。历史详情无需迁移。

## 自足性要求

详情必须让维护者无需模型二次推理即可理解并裁决。每项必须明确说明背景、裁决目标、影响范围、风险、推荐方案与推荐理由，并至少提供两个可选方案；每个方案都必须同时列出收益和代价。

## 规范结构

```markdown
### {AN-N|PL-N|CD-N|HD-N}：{标题} [needs-human-decision]

- **背景**：{为何需要裁决；已知事实与约束}
- **裁决目标**：{本次必须确定的唯一选择}
- **影响范围**：{受影响的功能、文件、用户或后续先例}
- **风险**：{错误选择、延期或不裁决的风险}
- **推荐方案**：{方案 A/B/...}
- **推荐理由**：{基于收益、代价和约束的理由}

#### 方案 A：{名称}

- **收益**：{选择该方案的收益}
- **代价**：{选择该方案的成本与局限}

#### 方案 B：{名称}

- **收益**：{选择该方案的收益}
- **代价**：{选择该方案的成本与局限}
```

可增加方案 C 或补充证据，但不得省略上述字段或把多个方案压缩为无法分别比较的一行。标题 ID 必须与 task.md `## 审查分歧账本` 行一致，evidence 必须指向该标题的稳定锚点。

## 裁决闭环

使用 `ai task decisions <task-ref> <序号|账本ID>` 查看完整详情，使用 `ai decide <task-ref> <序号|账本ID> <裁决内容>` 写入裁决。`ai decide` 负责把目标行更新为 `human-decided`、创建独立 `HDR-N` 记录、更新 evidence 与活动日志；不得手工模拟其中一部分写入。
