# 并发风险检视

## 适用范围

当变更触及异步协调、共享状态、锁、重试、幂等、竞态、取消或超时时使用。

## 检视问题

- 共享状态的所有权、原子边界和可见性是否明确。
- 重试、超时、取消和重复交付是否保持幂等且不会泄漏资源。
- 竞争顺序和失败交错是否会产生丢失更新、重复副作用或死锁。

## 证据要求

记录关键状态转换、事件顺序和同步边界；使用确定性并发测试、调用链或数据流支撑结论。

## 常见反例

- 单次顺序执行通过就推断并发安全。
- 只检查加锁存在，不检查锁粒度、顺序和释放路径。
- 用随机压力测试的单次成功替代可解释证据。

## 无法闭环时

可重现的竞态或资源泄漏形成 finding；需要真实调度器或负载环境的检查进入 manual-validation；未覆盖交错记录为 gap。
