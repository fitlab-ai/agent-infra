# 迁移与兼容风险检视

## 适用范围

当变更触及持久化格式、schema、配置/frontmatter、兼容读取、迁移或回滚行为时使用。

## 检视问题

- 旧数据或旧配置能否被安全读取，写入后的版本边界是否明确。
- 迁移是否可重复执行，部分失败后能否恢复或继续。
- 回滚路径是否与新旧格式的兼容窗口一致。

## 证据要求

记录旧输入到新状态的转换、版本判定和失败状态；优先使用迁移测试、fixture、状态转换或规范冲突。

## 常见反例

- 只验证全新安装，不验证已有状态。
- 假设迁移一次成功，忽略重试和部分写入。
- 用格式存在性测试替代数据语义验证。

## 无法闭环时

可复现的数据损坏或兼容失败形成 finding；需要真实历史数据的验证进入 manual-validation；缺少样本或回滚证据时记录 gap。
